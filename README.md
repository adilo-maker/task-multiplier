# Task Multiplier — Множитель задач для OrcaSlicer

Нативный плагин OrcaSlicer, который печатает одну и ту же деталь несколько раз
подряд в одном G-коде. Стартовый и конечный G-код выполняются **один раз**,
повторяется только тело печати. Между копиями можно сбрасывать деталь,
парковать голову, подавать сигнал, протягивать филамент и делать длинные паузы.

**Версия:** 1.0.0 · **Лицензия:** MIT · **Платформа:** Windows · **Автор:** by:adilo321

**Orca Cloud:** [Task Multiplier 1.0.0](https://cloud.orcaslicer.com/p/5e1413482d47)

Плагин написан при помощи ИИ.

## 1. Возможности

- **Размножение тела печати.** Стартовый и конечный блоки остаются в файле
  один раз, тело печати повторяется N раз.
- **Сброс деталей.** Промежуточные копии сбрасываются всегда, чтобы освободить
  стол. Галочка **«Сброс последней детали»** решает, сбросить ли последнюю
  копию или оставить её на столе. Способ сброса выбирается всегда:
  - **«Головой»** — проход печатающей головой;
  - **«Балкой оси X»** — резкий рывок балки по Y.
- **Бесконечный и конечный цикл силами прошивки:**
  - Klipper — `SDCARD_LOOP_BEGIN COUNT=0` / `SDCARD_LOOP_END`;
  - Marlin — `M808 L0` / `M808`.
- **Автоопределение прошивки** по G-коду с ручным переопределением.
- **Парковка головы** отдельной командой `G28`.
- **Сигнал, протяжка филамента и длинные паузы** между копиями.
- **Защита от повторной обработки** уже размноженного файла.
- **Автоматическая миграция** старых настроек `eject_mode`, `drop`,
  `drop_gcode`, `bed_eject_gcode`.
- **Двуязычный интерфейс настроек**: английский по умолчанию, русский по
  выбору.

## 2. Требования

- **OrcaSlicer 2.5.0-rc или новее** с поддержкой нативных Python-плагинов
  (slicing-pipeline). Отдельный Python устанавливать не нужно: OrcaSlicer
  использует встроенный интерпретатор.
- Для обычного режима (без цикла) специальных требований к прошивке нет.
- Для цикла:
  - **Klipper**: раздел `[sdcard_loop]` в `printer.cfg` и печать с SD или
    виртуальной SD (Mainsail/Fluidd). При потоковой печати по USB цикл не
    работает.
  - **Marlin**: включённые `SDSUPPORT` и `GCODE_REPEAT_MARKERS`, печать с SD.

## 3. Установка

### 3.1. Через интерфейс OrcaSlicer (рекомендуется)

1. Скачайте `task_multiplier.py` из репозитория или релизного архива.
2. Откройте диалог **«Плагины»** (в англ. интерфейсе — *Plugins*; кнопка
   «Открыть плагины» / *Open Plugins*).
3. Нажмите **«Импорт плагина»** (*Install Local Plugin*).
4. Выберите файл `task_multiplier.py`.
5. Убедитесь, что плагин включён, а возможность **Task Multiplier** активна.
6. Перезапустите OrcaSlicer, если он попросит.

Плагин не запрашивает сеть, процессы или чтение личных файлов. На этапе
постобработки OrcaSlicer сам разрешает запись в папку с G-кодом, поэтому
отдельные разрешения не нужны.

### 3.2. Из репозитория через PowerShell

```powershell
git clone <URL-репозитория> orca-task-multiplier
cd orca-task-multiplier
powershell -ExecutionPolicy Bypass -File .\install.ps1
```

Если репозиторий ещё не опубликован, используйте локальную папку `github`:

```powershell
cd "C:\путь\к\orca_task\github"
powershell -ExecutionPolicy Bypass -File .\install.ps1
```

Скрипт:

- копирует `task_multiplier.py` в
  `%APPDATA%\OrcaSlicer\orca_plugins\task_multiplier.py\`;
- создаёт `.install_state.json` в UTF-8;
- **не трогает** пользовательский `config.json`.

Можно указать другую папку плагинов:

```powershell
powershell -ExecutionPolicy Bypass -File .\install.ps1 `
  -OrcaPluginsDir "D:\OrcaSlicer\orca_plugins"
```

После установки перезапустите OrcaSlicer.

### 3.3. Где хранятся настройки

`%APPDATA%\OrcaSlicer\orca_plugins\config.json`, запись с
`"plugin_key": "task_multiplier"`. Если каких-то ключей нет, плагин берёт
значения по умолчанию. Редактировать файл вручную можно только при закрытом
OrcaSlicer.

При обновлении со старых версий настройки переносятся автоматически:

- `eject_mode = none` → «Сброс последней детали» выключен;
- `eject_mode = head` → сброс включён, способ «Головой»;
- `eject_mode = bed` / `custom` → сброс включён, способ «Балкой оси X»;
- старый `drop = true` и `drop_gcode` → «Балкой оси X» с сохранением
  пользовательского шаблона.

## 4. Быстрый старт

1. Откройте модель и выберите профиль принтера/пластика.
2. Откройте настройки плагина: **«Плагины» → Task Multiplier → Возможности /
   Настройки**.
3. Задайте **количество деталей**, при необходимости включите **«Сброс
   последней детали»** и выберите способ: **«Головой»** или **«Балкой оси X»**.
4. Нарежьте модель и экспортируйте G-код. Плагин срабатывает на шаге
   `psGCodePostProcess` и перезаписывает готовый файл.
5. Отправьте G-код на печать.

В заголовке G-кода появится строка вида:

```gcode
; TASK_MULTIPLIER: 3 copies, start/end G-code printed once, body repeated 3 times
```

## 5. Настройки

### 5.1. Основное

| Параметр | Описание |
| --- | --- |
| **Количество деталей за задание** | Сколько всего деталей печатать. Это общее число копий, а не «дополнительные повторы». |
| **Сброс последней детали** | Если включено, последняя деталь тоже сбрасывается со стола. Если выключено, она остаётся на столе, а промежуточные копии всё равно сбрасываются. |
| **Способ сброса** | `Головой` — проход печатающей головой; `Балкой оси X` — оригинальный рывок балкой из старой программы «Множитель задач». Список доступен всегда. |
| **Высота подъёма оси Z, мм** | Подстановка `{Z}` в шаблонах сброса. Для сброса головой ставится чуть выше высоты детали. |

Как работает сброс:

- **Головой** — подъём Z, проход головы по X вперёд и назад. Шаблон:
  `head_eject_gcode`.
- **Балкой оси X** — подъём Z и резкий рывок балки по Y. Шаблон:
  `beam_eject_gcode`.

Промежуточные копии сбрасываются **всегда**, чтобы на столе не оставалось
деталей. Последняя копия сбрасывается только при включённой галочке **«Сброс
последней детали»**; если она выключена, последняя деталь остаётся на столе.
Шаблоны сброса сохраняются в настройках независимо от галочки.

### 5.2. Между копиями

| Параметр | Описание |
| --- | --- |
| **Парковка головы командой G28** | Отдельный выключатель. Если не нужен сброс/парковка головой, оставьте выключенным. Шаблон: `parking_gcode`. |
| **Звуковой сигнал** | `M300` после каждой детали. Шаблон: `beep_gcode`. |
| **Протяжка филамента** | Код протяжки перед каждой деталью. Шаблон: `clean_gcode`. |
| **Начальная координата протяжки** | Стартовое значение `{X}`/`{Y}`. |
| **Шаг координаты на копию** | Сдвиг протяжки на каждой следующей копии. |
| **Ось протяжки** | `X` или `Y`. |

Если в теле G-кода есть строка `{CLEAN}`, она заменяется кодом протяжки с
нужной координатой. Если строки нет, код протяжки вставляется перед телом
очередной копии.

### 5.3. Длинная пауза

| Параметр | Описание |
| --- | --- |
| **Делать паузу между партиями** | Включает паузы по счётчику деталей. |
| **Пауза через каждые, деталей** | Например, `40` — пауза после каждой 40-й детали. |
| **Длительность паузы, минут** | `G4 S<секунды>`. |
| **Выполнять G28 после паузы** | Возврат в ноль после паузы. |
| **Восстанавливать температуры после паузы** | Повторно задаёт и ждёт температуру сопла/стола. |

В **циклическом режиме** паузы по счётчику не вставляются: прошивка не
сообщает номер итерации. Сброс, парковка, сигнал и протяжка в цикле работают.

### 5.4. Цикл (бесконечная печать)

| Параметр | Описание |
| --- | --- |
| **Повторять тело силами прошивки** | Тело печати записывается в файл один раз, повторяет прошивка. |
| **Прошивка** | `Авто`, `Klipper — SDCARD_LOOP`, `Marlin — M808`. |
| **Повторов (0 = бесконечно)** | `0` — бесконечный цикл; `N` — ровно N повторов. |

Как работает автоопределение:

1. Ищется строка `; gcode_flavor = ...` в конфиг-блоке OrcaSlicer в конце
   файла. `klipper` → Klipper, `marlin`/`marlin2` → Marlin.
2. Если в G-коде есть Klipper-команды (`SET_VELOCITY_LIMIT`,
   `BED_MESH_CALIBRATE`, `EXCLUDE_OBJECT_START`, `PRINT_START`,
   `SAVE_VARIABLE`) — выбирается Klipper даже при профиле Marlin.
3. Если ничего не найдено — плагин предполагает Klipper и добавляет в G-код
   предупреждение `WARNING: firmware auto-detect failed...`. В этом случае
   лучше выбрать прошивку вручную.

### 5.5. Завершение и прочее

| Параметр | Описание |
| --- | --- |
| **Выключить нагрев и моторы в самом конце** | Дополнительный `turnoff_gcode` перед концом файла. |
| **Отключить автосохранение позиции (M413 S0)** | Добавляет `M413 S0` после стартового блока. |
| **Комментарии-разделители копий** | Служебные комментарии `; TASK_MULTIPLIER: ...`. |
| **Пометка в заголовок G-кода** | Информационная строка в шапке файла. |

### 5.6. Подстановки в шаблонах

| Подстановка | Значение |
| --- | --- |
| `{Z}` | Высота подъёма `z_lift`. |
| `{X}`, `{Y}` | Координата протяжки: `clean_start + clean_step * (INDEX - 1)`. Это **не** размер стола. |
| `{COUNT}`, `{TOTAL}` | Всего копий. В бесконечном цикле — `0`. |
| `{INDEX}`, `{COPY}` | Номер текущей копии. В цикле — `1`. |
| `{CLEAN}` | Код протяжки целиком. |

## 6. Бесконечный режим

### 6.1. Klipper

В `printer.cfg` должен быть раздел:

```ini
[sdcard_loop]
```

Файл печатается через виртуальную SD (Mainsail/Fluidd). Плагин формирует:

```gcode
; стартовый блок — один раз
SDCARD_LOOP_BEGIN COUNT=0
; тело печати — один раз
; сброс/парковка/сигнал/протяжка
SDCARD_LOOP_END
; конечный блок — после остановки цикла
```

Остановка цикла: отправьте в консоль Mainsail/Fluidd команду

```gcode
SDCARD_LOOP_DESIST
```

Klipper завершит текущую итерацию, выйдет из цикла и выполнит конечный G-код
(выключение нагрева, моторов и т.д.).

### 6.2. Marlin

Нужны `SDSUPPORT`, `GCODE_REPEAT_MARKERS` и печать с SD. Плагин формирует:

```gcode
; стартовый блок — один раз
M808 L0
; тело печати — один раз
; сброс/парковка/сигнал/протяжка
M808
; конечный блок
```

- `M808 L0` — бесконечный цикл.
- `M808 L<N>` — ровно N повторов; после них выполнится конечный блок.
- Бесконечный цикл на Marlin нельзя корректно завершить командой: конечный
  блок выполнится только после остановки печати вручную (а при аварийной
  остановке Marlin обычно не дочитывает файл).

### 6.3. Ограничения цикла

- Не работает при потоковой передаче G-кода по USB/серийному порту
  (OctoPrint и подобные). Нужна печать с SD/виртуальной SD.
- Периодические паузы по счётчику деталей в цикле не вставляются.
- Если прошивка определена неверно, цикл не запустится. Выберите прошивку
  вручную в настройках.
- Для Klipper `SDCARD_LOOP_*` требует включённого `[sdcard_loop]`; иначе
  Klipper сообщит неизвестную команду.

## 7. Как устроен результат

Обычный режим (3 копии, сброс последней детали выключен):

```text
заголовок + стартовый G-код      один раз
  копия 1 + сброс/парковка/...
  копия 2 + сброс/парковка/...
  копия 3 + парковка/сигнал/...  (последняя деталь остаётся на столе)
конечный G-код + статистика      один раз
```

Если включён **«Сброс последней детали»**, после копии 3 также выполняется
сброс.

Цикл (тело записывается один раз):

```text
заголовок + стартовый G-код      один раз
SDCARD_LOOP_BEGIN COUNT=0        (или M808 L0)
  тело печати + сброс/парковка/...
SDCARD_LOOP_END                  (или M808)
конечный G-код + статистика      один раз (после остановки цикла)
```

Стартовый блок — всё до первого `;LAYER_CHANGE` / `;LAYER:`. Конечный блок —
от последнего `;TYPE:Custom` перед `; EXECUTABLE_BLOCK_END`. Блок статистики и
конфигурации OrcaSlicer не дублируется.

## 8. Безопасность и ограничения

- Перед первым запуском проверьте шаблоны сброса на своём принтере. Движения
  головы и балки могут выходить за пределы рабочей области, если координаты
  в шаблонах не соответствуют вашему принтеру.
- Для сброса головой и балкой `z_lift` должен быть чуть выше высоты детали,
  иначе инструмент столкнётся с деталью. Начните с заведомо безопасной высоты
  и используйте аварийную остановку.
- Плагин не проверяет кинематику и ограничения принтера: он только вставляет
  G-код.
- При повторной обработке уже размноженного файла плагин ничего не делает и
  сообщает об этом — это защита от случайного `N × N` копий.
- Если отключены и комментарии-разделители, и пометка в заголовке, защита от
  повторной обработки не сможет распознать файл. Оставьте хотя бы один из
  этих параметров включённым.

## 9. Диагностика

| Симптом | Что проверить |
| --- | --- |
| Плагин не появился в списке | Правильная ли папка `...\orca_plugins\task_multiplier.py\`, есть ли внутри ровно один `.py` и `.install_state.json`; перезапущен ли OrcaSlicer. |
| Плагин не срабатывает при экспорте | Включён ли плагин и активна ли возможность Task Multiplier; смотрите лог OrcaSlicer. |
| В G-коде нет пометки `TASK_MULTIPLIER` | Возможно, G-код экспортирован без постобработки или плагин отключён. |
| Цикл Klipper не работает | Есть ли `[sdcard_loop]`; печать идёт с виртуальной SD, а не потоком по USB. |
| Цикл Marlin не работает | Включены ли `SDSUPPORT` и `GCODE_REPEAT_MARKERS`; печать с SD. |
| Неверно определилась прошивка | Выберите Klipper/Marlin вручную в настройках плагина. |
| Файл обработан повторно | Плагин сам пропускает уже обработанный файл; нарежьте модель заново. |

## 10. Разработка и тесты

Требования для разработки: Windows, Python 3.12+.

Все проверки одной командой:

```powershell
py tests\run_all.py
```

Отдельные тесты:

```powershell
py tests\test_transform.py
py tests\test_plugin_api.py
py tests\check_ui.py
```

Тесты используют встроенный сэмпл `testdata\sample_plate.gcode`. Другой
G-код можно указать переменной окружения:

```powershell
$env:ORCA_SAMPLE_GCODE = "D:\gcode\sample.gcode"
py tests\test_transform.py
```

Предпросмотр интерфейса настроек с макетом `window.orca`:

```powershell
py tests\make_ui_preview.py
```

Для проверки миграции старых настроек:

```powershell
$env:ORCA_PREVIEW_LEGACY = "1"
py tests\make_ui_preview.py
```

Сборка релизного архива:

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\package.ps1
```

Архив появится в `dist\task_multiplier-<версия>.zip` и будет содержать
плагин, установщик, README, лицензию и changelog.

CI в GitHub Actions запускает тесты на Python 3.12 и 3.13, а также собирает
релизный архив. Конфигурация: `.github/workflows/tests.yml`.

- промежуточные копии сбрасываются всегда, последняя — по галочке «Сброс
  последней детали»;
- способ сброса: «Головой» или «Балкой оси X»;
- миграция старых `eject_mode`, `drop`, `drop_gcode`, `bed_eject_gcode`;
- отдельная парковка `G28`;
- бесконечный и конечный цикл Klipper/Marlin;
- автоопределение прошивки и ручное переопределение;
- защита от повторной обработки;
- двуязычный интерфейс настроек: английский по умолчанию, русский по выбору;
- плагин написан при помощи ИИ.
